# The Polite Scraper

FlyRank Internship — a small, polite scraping pipeline for
[Books to Scrape](https://books.toscrape.com): fetch → extract →
normalize → validate → store → report.

## Target classification (Stage 0)

- **Site:** [books.toscrape.com](https://books.toscrape.com), a
  fictional bookstore built specifically for scraping practice.
  [toscrape.com](https://toscrape.com) — the sandbox's own homepage —
  describes it as *"a fictional bookstore that desperately wants to be
  scraped. It's a safe place for beginners learning web scraping."*
- **Scope:** the first 3 catalogue pages only (60 books total), followed
  by each book's own detail page.
- **Data collected:** title, price, availability, star rating,
  description, and each record's source page and fetch time — all
  already present in the page's own HTML, nothing scraped that required
  login, payment, or bypassing any restriction.
- **robots.txt result:** `GET https://books.toscrape.com/robots.txt`
  returns **404 Not Found** — verified directly, not assumed. No robots
  file exists. Per the assignment's own framing, a missing file is not
  permission on its own — it's just a missing file. The actual basis for
  scraping this site is the sandbox's explicit, stated purpose above.
- **I will not reuse this code on another site without checking its
  rules and terms first.**

## How to run it

```bash
npm install
npm start
```

Writes `output/books.json`, `output/errors.json`, and
`output/run-report.json`. Run it again and you'll see mostly `CACHE HIT`
lines — the site is only really asked once per page.

To prove the Stage 5 failure-survival checkpoint (one deliberately broken
URL injected into the run):

```bash
FORCE_BROKEN_URL=1 npm start
```

### Run the tests

```bash
npm test
```

6 unit tests covering price normalization, relative→absolute URL
resolution, a missing description, duplicate-URL de-duplication, and one
fully malformed fixture — all run against saved HTML fixtures in
`test-fixtures/`, no network required.

## Politeness rules this scraper follows

- **User-agent:** `FlyRankInternshipA9/1.0
  (+https://github.com/Shivam6050/flyrank-backend-ai-engineering-internship)`
  — every real request identifies itself and links back to this repo.
- **Timeout:** every request gives up after 10 seconds rather than
  hanging forever.
- **Delay:** at least 500ms between real requests. Cached reads skip the
  delay entirely — they never leave the machine.
- **Cache:** every fetched page is saved to `cache/` (git-ignored) and
  read from there on subsequent runs, so development doesn't repeatedly
  hit the site.
- **Status check:** only `200` is treated as a real page. A `5xx` or a
  network error gets exactly one retry after a short pause; a `404` or
  `403` is never retried — asking again won't change either answer.

## Record schema

| Field | Type | Notes |
|---|---|---|
| `title` | string | |
| `product_url` | string (URL) | canonical identity — de-duplicated on this field |
| `price_text` | string | raw, e.g. `"£51.77"` |
| `price_gbp` | number | clean value, e.g. `51.77` |
| `availability_text` | string | raw text as shown on the page |
| `rating_text` | string \| null | raw word, e.g. `"Three"` |
| `rating_value` | number (1–5) \| null | clean value, e.g. `3` |
| `description` | string \| null | `null` when the page has none — never invented |
| `source_page` | string (URL) | which catalogue page this book was discovered on |
| `fetched_at` | string (ISO datetime) | provenance — when this record was fetched |

Every record is validated against this schema (`src/schema.js`, Zod)
before being written. A record that fails validation is written to
`errors.json` with a reason instead of `books.json`.

## Why this assignment needed no browser

Every field this scraper collects — title, price, availability, rating,
description — is already present in the HTML the server sends on first
response; none of it is generated by JavaScript after the page loads. A
browser would only add startup cost and memory for content that was
never hidden in the first place.

## Ethics note

Use an official API instead of scraping wherever one exists — it's more
stable for you and less load on them. Never bypass a login, a paywall, or
a block; if a site says no, that's the answer. Collect only the fields
you actually need, not everything reachable. None of that was a real
constraint here, since Books to Scrape exists specifically to be scraped
— but the habit is the point, not the exception.

### Full Prompt Used

> "Build a Node.js web scraper in JavaScript using Cheerio and Zod for books.toscrape.com. Scrape the first 3 catalogue pages by following next page links, extract all 60 book URLs, and visit each detail page. Collect title, product_url, price_text, price_gbp, availability_text, rating_text, rating_value, description, source_page, and fetched_at. Validate each record with Zod. Include politeness rules (user-agent header, 500ms delay between fetches, local caching to cache/ directory, error handling for broken pages). Output valid records to output/books.json."

### Key Findings & Analysis

1. **What the AI did better:**
   - Concise single-file structure in `ai-version/index.js` that compiles inline selector logic quickly.

2. **What the AI got wrong or silently skipped:**
   - **No structured run report:** The AI version omitted generating `run-report.json` with execution provenance (start time, duration, cache hits, invalid records, failed pages).
   - **Narrow Error handling:** The AI version did not distinguish between network retries (5xx errors) and non-retryable 404/403 status codes.
   - **Missing export formats:** Did not generate CSV export or observability dashboard.

3. **What my prompt forgot to say:**
   - Explicitly request generating `output/run-report.json` with execution timing and cache statistics.
   - Mandate specific retry rules (1 retry on 5xx/timeout, 0 retries on 404/403).
